# Shared Sticker-Pack UI Acceptance Record

## Implemented

- `StickerPack` appends optional `coverImageUrl` and boolean `defaultInstall` with
  backward-compatible defaults. Existing PAG representation fields are preserved.
- `StickerPanel(onSend)` starts on Installed. Installed server rows provide cover
  tabs, persisted order and selection. Only the selected pack's visible sticker
  rows are composed in a lazy grid.
- Store and Manage use lazy pack cards with cover, localized name and count.
  Store never renders sticker send cells. Manage exposes uninstall and up/down.
- Mutations call the existing `StickerCatalog` methods and reconcile using
  `installed()`, including ambiguous write failures. Installation state is never
  inferred from `defaultInstall`, nor populated from a local Apple catalog.
- The MessagePage smiley entry and existing sticker entry use the same panel.
  Legacy EMOJI panel state aliases StickerPanel. There is no product entry to the
  previous Unicode category picker; raw Unicode typing and inline rendering are
  unchanged. Sends still create `StickerMessagePayload(stickerId, imageUrl)`.
- Uninstall changes installation state only; UI history rendering and resource
  resolution remain independent. Existing installed offline packs remain usable.
- New management/count translations are in `i18n/PrivChatStickerPanelStrings.kt`
  for English, Simplified/Traditional Chinese and Vietnamese.

## Stable Acceptance API

`StickerPanelTestTags` exports Panel, Installed, Store, Manage, Refresh, Toggle and
SelectedPack plus pack/card/cover/name/count/grid/install/uninstall/up/down/send
helpers. Each helper includes the server pack or sticker ID. An install button
only becomes an uninstall button after authoritative installed-list readback.

The UI consumes the existing StickerCatalog and server IDs. The app adapter owns
conversion of wire `defaultInstall` integer 0/1 to the shared boolean and cover
URL resolution. Pack generation, actual 21-pack publication, default-install
tombstones, database persistence and real onSend/UI/history acceptance remain
backend/app/acceptance-agent responsibilities.
